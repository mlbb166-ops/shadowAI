# Visual validation notes

Pada build lokal, landing page tampil utuh pada viewport desktop tanpa aset hilang. Metadata browser sudah berubah ke judul kanonis. Landing masih perlu diverifikasi ulang setelah penghapusan klaim demo.

Halaman registrasi tampil rapi dalam dua kolom dan seluruh field terlihat tanpa scroll pada viewport desktop. Ditemukan dua teks legacy yang perlu dihapus: footer kecil mengklaim Box-Cox LMS WHO/TKPI sebagai kemampuan aktif, dan tautan "Portal Kerja Kader" masih menuju route yang telah dinonaktifkan. Keduanya akan diperbaiki sebelum validasi dashboard.
Registrasi release candidate telah diperiksa ulang: CTA portal kader legacy dan klaim WHO/TKPI aktif sudah hilang. Layout desktop tetap utuh, label dan field terbaca, validasi password menyebut minimum 10 karakter, dan checkbox consent dapat dipilih. Akun uji visual diisi untuk melanjutkan pengujian dashboard.
Validasi consent bekerja dan menahan submit ketika React state belum menerima perubahan checkbox dari operasi fill otomatis. Klik langsung mengaktifkan checkbox. Ini bukan bug UI pengguna; pesan error terlihat jelas dan form mempertahankan nilai lain.
Dashboard desktop release candidate tampil dengan hierarki yang jelas: satu CTA prioritas, tiga kartu status, asisten, aktivitas, pencarian, dan kesiapan data. Tidak ada data anak demo; profil kosong ditampilkan jujur dan kontrol pengukuran/Telegram disabled. Sidebar menampilkan akun aktual. Modal tambah profil terpusat, fokus visual baik, dan field inti terlihat tanpa scroll.
Form profil berhasil menyimpan Naya, menutup modal, memperbarui hero dan CTA ke pengukuran pertama, serta mengaktifkan tombol catat pengukuran. Job onboarding dipicu tetapi kartu aktivitas belum memperbarui dirinya segera saat worker masih memproses; dashboard akan ditambah polling terbatas selama ada pending job dan indikator status antrean.
Input pertanyaan agent muncul pada textarea dashboard dan tombol submit aktif. Pengujian berikutnya memverifikasi respons model nyata, delapan tahap, dan kartu audit.
Submit agent menampilkan state loading dan menonaktifkan tombol selama pemrosesan. Screenshot Chromium 390×844 memverifikasi layout autentikasi mobile: kolom berubah menjadi satu alur vertikal, teks tidak terpotong, dan tidak ada overflow horizontal. Karena profil Chromium terpisah tidak membawa cookie browser terkelola, validasi dashboard mobile penuh dilakukan berikutnya dengan browser otomatis berlogin.
